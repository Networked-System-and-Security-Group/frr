## 2. 必须修复的问题

### 2.1 保持既有 ZAPI 编号不变

`lib/zclient.h` 将 `ZEBRA_GRE_ADD`、`ZEBRA_GRE_DELETE` 插入已有 enum 中间，导致后续 ZAPI 消息编号整体移动，破坏旧版 zebra/client 的兼容性。新增编号应追加到 enum 末尾，或显式固定所有既有编号；同时检查 `lib/zclient.c` 和 `zebra/zapi_msg.c` 中按编号索引的名称、编码和分发数组。

该修复应单独提交，便于审查和回溯，且必须用旧消息集合做兼容性回归。

### 2.2 修复 deferred FIB 失败后的 desired/install 一致性

`midrd/midr-dp-backend.c` 中，`update_deferred()` 返回成功后 SPF runtime 的 `desired` 可能已经前进；异步 deferred flush 随后失败时，不可重试错误路径会清空 pending，但没有保证 desired 回滚或完整 replay/resync。这样可能出现运行时认为路由已经安装、而实际 FIB 缺少部分路由的永久分裂。

需要明确失败语义并实现其中一种完整路径：失败时回滚对应 desired generation，或保留失败批次并触发完整 replay/resync；清空 pending 前必须保证后续一定会重新产生全部缺失的安装操作。测试需覆盖部分批次成功、批次失败、重连后恢复以及恢复期间新的 desired 更新。

### 2.3 恢复重试不能因达到上限而永久停滞

当前 recovery 达到最大重试次数后只记录“等待 zebra reconnect”。如果 socket 尚未断开但持续发送失败，恢复流程可能永久停滞。需要在达到上限后保留明确的待恢复状态，并由定时器、连接状态变化或显式重同步再次触发，而不是只等待一个可能永远不会到来的 reconnect 事件。

## 3. 建议一并修复的错误路径

以下项目不一定阻塞第一轮联调，但应在同一修复序列中完成：

- `dp_installed_set()` 检查并处理 `dp_paths_dup()` 和 hash 插入失败；
- `midr_zebra_backend_register()` 复制外部 ops 内容或明确其生命周期，避免保存短生命周期指针；
- `midr_gre_registry_add()` 检查 `calloc()` 失败；
- 相同接口名绑定新的 GRE 端点时同步更新 registry，不保留旧端点；
- 清理新增数据面文档的 trailing whitespace 和文件末尾多余空行，使 `git diff --check` 通过。
