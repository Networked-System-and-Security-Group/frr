# MIDR Single-Instance Flooding: P3 Lifetime and Refresh

## Scope

P3 adds the runtime lifetime path on top of the P2 canonical instance:

```text
Owner refresh
  -> higher sequence ACTIVE instance
  -> canonical age tracking
  -> expiry and active-view removal
  -> LSDB/TED rebuild
  -> conservative floor retention
```

The implementation does not restore Propagation Path, does not generate a
proxy withdrawal for a remote owner, and does not change the public TED API.
P4 resynchronization and restart recovery, normal withdrawal coordination, and
third-group FIB integration remain outside this phase.

## Lifetime Parameters

The initial internal values are:

```text
L = 3,600,000 ms   maximum instance age
R =   300,000 ms   owner refresh period
B =         1,000 ms   forwarding age budget
```

They are compile-time implementation parameters in this phase. No production
CLI was added and runtime parameter changes are not supported.

The canonical store records the received age and a monotonic-clock timestamp.
The current age is calculated without rewriting the stored object. Clock
rollback is rejected and age arithmetic saturates at `L`.

## Canonical Expiry

The lifetime sweep runs from the main event loop in bounded batches. When an
instance reaches `L`:

- an ACTIVE instance is removed from the active RIB view and therefore from
  LSDB/TED input;
- a WITHDRAWN instance stops being advertised, while its sequence floor is
  retained;
- expiry never creates a withdrawal owned by an intermediate node;
- a later higher-sequence valid instance may replace the floor.

Expiry is represented by a retryable canonical event. The RIB removes the
corresponding FRR path and lets the existing LSDB/TED transaction derive the
new active view. `MP_UNREACH` generated by that local advertisement cleanup is
not an owner withdrawal.

## Owner Refresh

The Owned store uses one store-level refresh scheduler. Each locally advertised
object is refreshed by allocating a higher sequence while retaining the last
advertised semantic payload. Link refresh therefore uses the already published
canonical cost and does not bypass the measurement interval or cost deadband.

Refresh work is processed in bounded batches. Sequence allocation failure keeps
the previous object and leaves the existing retry path responsible for a later
attempt; no fabricated sequence or withdrawal is emitted.

A refresh changes the control-plane version and is eligible for propagation, but
does not by itself change the topology-derived TED content.

## Age on Output

MIDR output is restricted to one semantic NLRI per UPDATE. At serialization,
the sender derives the current age from the canonical instance and adds the
configured forwarding budget. An object that has reached `L` is not emitted as
an unexpired instance. This keeps age from being shared by unrelated objects
inside one UPDATE attribute snapshot.

The existing BGP output queue still owns the final TCP byte stream. P3 does not
claim that a queue-level progress timestamp proves an end-to-end delivery
bound; the transport-budget proof and abnormal slow-write recovery remain
explicit acceptance work.

## Semantic TED Stability

LSDB state comparison and remote Provider notification compare object content
without the LS sequence. Therefore:

```text
ACTIVE 105, payload X
  -> ACTIVE 106, payload X
```

updates canonical/RIB propagation state but does not advance TED generation or
repeat a semantic Provider callback. A payload, scope, usability, membership,
cost, or prefix change still creates a new TED generation.

## Floor Retention

The canonical store records the time at which the accepted version entered the
local store. Floor collection is implemented behind an explicit gate and is
disabled in production until the `H = L` transport-budget conditions are
proved. This prevents a fixed timer from being mistaken for a complete safety
proof. Test code can enable collection to verify the retention boundary.

Collection also requires the floor to have no current instance and no pending
canonical event for the same identity. External RIB, LSDB, TED, and send
references remain the responsibility of the caller and are not freed by the
canonical store itself.

## Verification

The P3-focused checks cover:

- age saturation, monotonic-clock rollback, expiry boundaries and bounded sweep;
- ACTIVE expiry, WITHDRAWN floor retention, higher-version replacement and
  delayed floor collection;
- owner refresh sequence growth with unchanged payload;
- semantic no-op refresh without TED generation or Provider callback changes;
- single-NLRI output packet construction and existing P2 packet behavior;
- the full MIDR component regression set.

The current branch verification includes clean GCC builds of `bgpd/bgpd` and
the MIDR component targets. The production floor-collection gate remains
closed pending the separate transport-budget and abnormal-delay proof.
