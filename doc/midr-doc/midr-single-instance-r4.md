# MIDR single-instance flooding: R4 lifecycle and diagnostic evidence

dead allocation branch identified as N-5. The implementation is split across

The existing single-instance flooding model, canonical RIB authority, TED
READY/NOT_READY barrier, aging policy and production floor-GC default are
unchanged. No protocol field, configuration command or new convergence rule
was added.

## Owned and shutdown diagnostics

Owned withdrawal and refresh paths now expose process-lifetime failure counts
and the most recent non-zero error. The counters cover sequence generation,
identity reconciliation, link suppression, periodic refresh and shutdown
retry paths. Failed operations leave the advertised state, old instance and
refresh cursor unchanged, so the existing reconcile or retry cycle can make
progress after recovery. Reconcile and refresh batches emit one aggregate
warning with the failure count and first error.

Shutdown synchronization records one generation failure per teardown cycle.
The final log result remains explicit and distinct: `COMPLETE` means generated
and written, `DEGRADED` means generated but not fully delivered before the
deadline, and `GENERATION_FAILED` means an object could not be generated by
teardown. `show midr owned` and `show midr sync` expose these counters.

## RIB lifetime and peer state

The lifetime pass returns the first real sweep or GC error after applying all
events successfully generated in the pass and still running safe GC. Normal
`-EAGAIN`, `-ENOENT` and reclaim-callback vetoes are not counted as failures;
the next one-second pass retries automatically. Repeated identical errors
are logged once and recovery is logged once. A test-only canonical event
limit makes upsert and expire allocation failures deterministic. The
`XCALLOC`-based advertisement allocation no longer carries an unreachable
NULL rollback branch; recoverable attribute/canonical failures still preserve
the previous state.

When a peer leaves Established, only its advertisement records are removed
from every identity. Canonical instances, selected paths, LSDB state, TED
state and other peers are retained. The cleanup is idempotent, allowing a
reconnected or address-reused peer to advertise a fresh snapshot without an
old pointer suppressing it.

## GR/LLGR filtering

The ordinary OPEN and dynamic capability parsers consume and ignore only the
exact `(AFI_BGP_LS, SAFI_MIDR_LS)` GR/LLGR tuples. They do not set MIDR
restart, preserve or LLGR AF capability bits and do not reject the capability,
OPEN or session. Other tuples in a mixed capability continue through the
existing AF-specific logic. `show midr sync` reports separate cumulative GR
and LLGR ignored-tuple counters.

## Completion lifetime and lock discipline

Each queued packet has a session-list reference. Once a writer claims a
packet, the completion event receives a second reference while the packet is
removed from the registry. Registry lookup and state transition occur under
`midr_sync_packets_mutex`; event scheduling happens after unlocking. Session
teardown releases only its list reference and does not cancel an already
claimed completion. The event validates session token, connection and
generation before applying results, so late or duplicate completions are
harmless. The test-only completion drain covers completions claimed before a
session teardown.

## Boundaries

R4 establishes in-process lifecycle safety and observability. It does not
replace R5 multi-node withdrawal, reconnect, restart, normal-teardown or
shortened-lifetime long-stability scenarios. Production floor GC remains
disabled by default, and the conditional `H = L` proof remains subject to the
R2 age-budget assumptions. Independent MIDR extraction remains P7 work.
